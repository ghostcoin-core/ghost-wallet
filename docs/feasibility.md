# Feasibility

Phase 0 asks whether Ghost Wallet can do its work on an iPhone within limits a
user would accept. This page is generated by `scripts/feasibility-doc.js` from
`docs/feasibility.template.md` and the benchmark results
(`bench-results.json`, copied off the phone by `scripts/pull-results.sh`). The
numbers come from real-device runs; until those runs are recorded, the results
below are empty.

## Minimum phone

Minimum phone: iPhone 12 (iPhone13,2), until it is decided.

## Limits

Limits (`LIMITS` in `scripts/feasibility-report.js`). Miss any one, or record no number for it, and the run doesn't work. Every limit is a real-device limit: a simulator run can't pass.

- balance on screen ≤ 2 s from cache (restore note `balanceFromCacheSeconds`)
- restore time to first balance ≤ 10 s (restore note `timeToFirstBalanceSeconds`)
- every Summon proof ≤ 10 s (summon notes `proveMillis-<n>`)
- peak memory under the device's jetsam limit (`JETSAM_LIMIT_BYTES`), every benchmark
- no thermal state of serious or critical, every benchmark
- header checks within their budget (header-sync note `headerBudgetOk`)
- kill recovery covers every kill point (kill-recovery note `killPointsPassed`, "N of M" with N = M)

Also doesn't work: status not ok, a kill or crash, no device model, iOS version or simulator/real-device record, a failed check in the notes (proofs not all verified, accounts not all found, scan not complete, fewer than 2 RandomX caches in the worst case, a kill point lost or paid twice). Works with limits: a memory warning. Works: otherwise.

## Device rules

Each result records the device model, the iOS version, and whether it ran in
the simulator or on a real device. A simulator run is shown but never passes:
the limits above are real-device limits.
