# Ghost Wallet

An iPhone wallet for Ghost.

> **Experimental and unaudited.** Ghost Wallet is under construction. Do not use
> it with funds you cannot afford to lose.

## What it does

- **Quantum-safe accounts.** Create or restore a Ghost account, see the balance,
  send, and receive to fresh addresses. Accounts use lattice-based signatures
  with a hash-based rescue key. No elliptic-curve key exists anywhere in the app.
- **Vanish, Summon and Claim,** proved on the phone itself.
- **Phantom Keys on a card.** Write a Phantom Key to a blank NTAG 424 DNA card,
  then tap the card later to Summon or Claim. The card is never the only
  backup: every Phantom Key is also shown as words.

## How it works

- Secrets (account words, Phantom Keys, card keys and PINs) stay in native code
  and are never logged.
- There is no backend and no relayer. The app talks only to the Ghost node
  endpoint you choose, and checks the chain's headers itself instead of trusting
  that endpoint.
- The proving and key code is Ghost's own Rust library, built for iOS.

## Develop

The app is an Expo (SDK 54) project with expo-router, TypeScript and a dev
client. It targets iOS only and uses pnpm (`corepack enable` picks the pinned
version). The `ios/` folder is generated by `pnpm exec expo prebuild` and is
never committed.

### Native core

- `core/` is the Rust crate `ghost-wallet-core`. It depends on the `client`
  crate of [Ghost](https://github.com/ghostcoin-core/ghost), pinned to a commit,
  and exports it to the app through UniFFI. It holds no key or address code of
  its own. Run its tests with `cargo test --manifest-path core/Cargo.toml`.
- `modules/ghost-core/` wraps that crate as a React Native turbo module with
  uniffi-bindgen-react-native. `ubrn build ios --and-generate` (run by the Mac
  install script) builds the XCFramework for `aarch64-apple-ios` and
  `aarch64-apple-ios-sim` and writes the generated bindings; none of the
  generated files are committed.
- For now the home screen shows account 0 of Ghost's public test words (the
  counting-bytes test seed). Those are the only words that ever reach
  JavaScript.

### Run the gate

```sh
bash scripts/ci-gate.sh
```

It runs `pnpm install --frozen-lockfile`, then the typecheck (`tsc --noEmit`), ESLint, the Jest unit
tests and the Rust core tests (`cargo test --locked` in `core/`), and exits non-zero if any of them
fails. It runs on Linux and macOS with a Rust toolchain installed.

### Install on an iPhone

On the Mac Studio (Xcode, CocoaPods, Node 22 and rustup installed), connect the iPhone,
find its UDID with `xcrun devicectl list devices`, then run:

```sh
GHOST_WALLET_DEVICE=<udid> bash scripts/mac-install.sh
```

The script pulls `main`, runs `corepack enable`, `pnpm install
--frozen-lockfile`, adds the iOS Rust targets, tests the Rust core, builds it
as an XCFramework with its bindings, runs `pnpm exec expo prebuild --platform
ios --clean`, builds
a debug dev-client, installs it on that phone and prints what it installed.
Start the JS server afterwards with `pnpm exec expo start --dev-client`.
