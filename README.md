# Ghost Wallet

An iPhone wallet for Ghost.

> **Experimental and unaudited.** Ghost Wallet is under construction. Do not use
> it with funds you cannot afford to lose.

## What it does

- **Quantum-safe accounts.** Create or restore a Ghost account, see the balance,
  send, and receive to fresh addresses. Accounts use lattice-based signatures
  with a hash-based rescue key. No elliptic-curve key exists anywhere in the app.
- **Vanish, Summon and Claim,** proved on the phone itself.
- **Phantom Keys on a card.** Write a Phantom Key to a blank NTAG 424 DNA card,
  then tap the card later to Summon or Claim. The card is never the only
  backup: every Phantom Key is also shown as words.

## How it works

- Secrets (account words, Phantom Keys, card keys and PINs) stay in native code
  and are never logged.
- There is no backend and no relayer. The app talks only to the Ghost node
  endpoint you choose, and checks the chain's headers itself instead of trusting
  that endpoint.
- The proving and key code is Ghost's own Rust library, built for iOS.

## Develop

The app is an Expo (SDK 58) project with expo-router, TypeScript and a dev
client. It targets iOS only and uses pnpm (`corepack enable` picks the pinned
version) with the hoisted `node_modules` layout Expo needs (`.npmrc`). The
`ios/` folder is generated by `pnpm exec expo prebuild` and is never
committed. Expo's modules are built from source (`expo-build-properties`,
`ios.usePrecompiledModules: false`).

### Native core

- `core/` is the Rust crate `ghost-wallet-core`. It depends on the `client`
  crate of [Ghost](https://github.com/ghostcoin-core/ghost), pinned to a commit,
  and exports it to the app through UniFFI. It holds no key or address code of
  its own. Run its tests with `cargo test --manifest-path core/Cargo.toml`.
- `modules/ghost-core/` wraps that crate as a React Native turbo module with
  uniffi-bindgen-react-native. `ubrn build ios --and-generate` (run by the Mac
  install script) builds the XCFramework for `aarch64-apple-ios` and
  `aarch64-apple-ios-sim` and writes the generated bindings; none of the
  generated files are committed.
- The bench module (`modules/ghost-bench/`) calls the core through its Swift
  bindings. The install scripts generate them with UniFFI's own generator
  (`tools/uniffi-bindgen/`) into `modules/ghost-bench/ios/Generated/`, which is
  not committed; without them the core benchmarks report that the bindings are
  missing.
- For now the home screen shows account 0 of Ghost's public test words (the
  counting-bytes test seed). Those are the only words that ever reach
  JavaScript.

### Run the gate

```sh
bash scripts/ci-gate.sh
```

It runs `pnpm install --frozen-lockfile`, then the typecheck (`tsc --noEmit`), ESLint, the Jest unit
tests and the Rust core tests (`cargo test --locked` in `core/`), and exits non-zero if any of them
fails. It runs on Linux and macOS with a Rust toolchain installed.

### Install on an iPhone

On the Mac Studio (Xcode, CocoaPods, Node 22 and rustup installed), connect the iPhone,
find its UDID with `xcrun devicectl list devices`, then run:

```sh
GHOST_WALLET_DEVICE=<udid> bash scripts/mac-install.sh
```

The script pulls `main`, runs `corepack enable`, `pnpm install
--frozen-lockfile`, adds the iOS Rust targets, tests the Rust core, builds it
as an XCFramework with its bindings, generates the Swift bindings, runs `pnpm
exec expo prebuild --platform ios --clean` and `pod install`, builds a Release
app (the JavaScript is bundled, so no JS server is needed), installs and
launches it on that phone and prints what it installed.

### Test on a simulator

On the same Mac, with [Maestro](https://maestro.mobile.dev) and its Java
(`brew install openjdk@17`) installed, run:

```sh
bash scripts/sim-test.sh
```

It boots the simulator named by `GHOST_WALLET_SIM` (default `iPhone Duo`),
builds the current checkout the same way as the iPhone install but for the
simulator (arm64 only), installs it and runs `.maestro/bench.yaml` once per
benchmark in `BENCHES` (default `dummy summon kill-recovery`). Each benchmark
must report `<name>: ok`; a screenshot of each result is saved under
`sim-results/`. For example:

```sh
GHOST_WALLET_SIM="iPhone Duo" BENCHES="dummy summon" bash scripts/sim-test.sh
```

### Local test chain for the node benchmarks

The header-sync, restore and worst-case benchmarks need a Ghost node.
`scripts/test-chain.sh` runs one on the Mac (Go 1.26+ and rustup installed):

```sh
bash scripts/test-chain.sh start          # build ghost-node, init, mine, fund the test wallet
bash scripts/test-chain.sh wait 8600      # block until the chain reaches a height
bash scripts/test-chain.sh genesis        # print the block 0 RLP
bash scripts/test-chain.sh stop
```

`start` clones [ghost-node](https://github.com/ghostcoin-core/ghost-node) at a
pinned commit into `~/.ghost-wallet-testchain`, builds it with `make geth`,
initialises its internal-net genesis (chain 6777971, difficulty 1, 1-second
blocks) and mines with the internal net's public test miner key, as an archive
node answering JSON-RPC on port 8547 on every interface (8545 is left to the
node forwarded from the VM). The first time, it sends 1 GHOST to accounts 0, 3
and 7 of the counting-bytes test words. The chain is kept between runs.

When `BENCHES` names a node benchmark, `scripts/sim-test.sh` starts the chain,
waits for height 8600 (worst-case needs the second RandomX key, at 8449), and
writes the node URL and these test-only overrides into the simulator's
UserDefaults for `com.ghostcoin.wallet`:

| Key | Value |
| --- | --- |
| `benchNodeUrl` | `http://127.0.0.1:8547` |
| `benchTestChain.blockTime` | `1` |
| `benchTestChain.futureDrift` | `3600` (the miner runs up to an hour ahead) |
| `benchTestChain.genesisRlpHex` | the node's block 0 RLP |
| `benchTestChain.restoreAccountsExpected` | `3` |

The compiled values in `TestChainConfig.swift` (block time 30, future drift
30) are unchanged, and are used whenever an override is not set. Each node
benchmark gets 90 minutes. A full run:

```sh
BENCHES="dummy summon kill-recovery header-sync restore worst-case" bash scripts/sim-test.sh
```
